# 시놀로지 NAS에서 실행하기

## 지원 여부부터 확인

DSM 패키지 센터에서 **Container Manager**(이전 DSM에서는 **Docker**)를 설치할 수 있는 모델이 필요합니다. 모델별 지원이 다르므로 M5나 NAS가 있다는 사실만으로 실행 가능하다고 볼 수는 없습니다. DSM 7.2의 Container Manager ‘프로젝트’를 기준으로 아래 절차를 준비했습니다. 구형 Docker 패키지는 프로젝트 UI가 다르며 별도 설치 안내가 필요합니다.

이 파일과 Compose는 작성·정적 검사된 상태이며 **실제 Synology NAS에서 배포 검증하지 않았습니다.**

## 1. 파일 준비

File Station에서 `docker/timegarden` 폴더를 만들고 이 `server` 디렉터리의 내용을 넣습니다. `compose.yaml`, `Dockerfile`, `package.json`, 모든 `.mjs` 파일이 같은 폴더에 있어야 합니다.

`.env.example`을 복사해 `.env` 파일을 만들고 아래 세 값을 NAS에서 직접 입력합니다. 확장자 없이 이름이 정확히 `.env`인지 확인하세요.

```dotenv
SMARTTHINGS_TOKEN=본인이_발급한_토큰
SMARTTHINGS_DEVICE_ID=본인의_M5_장치_ID
APP_API_KEY=별도로_생성한_32바이트_이상_무작위_접속키
```

위 문자열은 설명용 예시이며 실제로 사용할 수 있는 인증 정보가 아닙니다. `.env`를 채팅이나 공개 공유 폴더에 올리지 마세요. NAS 관리자와 해당 폴더에 접근할 수 있는 사람은 비밀 설정을 읽을 수 있습니다. SmartThings 토큰 만료와 필요한 권한은 [서버 안내](README.md)를 확인하세요. 자동 토큰 갱신은 아직 구현되어 있지 않습니다.

## 2. Container Manager 프로젝트 생성

1. Container Manager → **프로젝트 → 생성**.
2. 프로젝트 이름: `timegarden`.
3. 경로: 앞서 파일을 넣은 `docker/timegarden` 폴더.
4. 기존 `compose.yaml`을 사용하는 방식으로 생성하고 빌드·시작합니다. DSM 버전에 따라 항목명이 다를 수 있습니다.
5. 컨테이너 로그에서 `TimeGarden timer service started`를 확인합니다. 상태가 `healthy`인지 확인하세요. 이 단계는 서버 시작 확인이며 M5 연동 검증은 아닙니다.

Compose는 의존성 설치가 필요 없는 Node.js 서버를 빌드합니다. 최초 실행에는 Docker Hub의 Node 이미지 다운로드가 필요합니다. NAS의 CPU에 맞는 이미지를 자동으로 선택하며 특정 플랫폼을 강제하지 않습니다.

서버는 NAS 로컬의 `127.0.0.1:3130`에만 연결됩니다. 아이폰에서 `NAS주소:3130`으로 직접 접속하는 방식이 아닙니다. NAS의 3130 포트가 이미 사용 중이라면 Compose의 왼쪽 포트와 아래 역방향 프록시 목적지 포트를 함께 변경하세요.

## 3. 아이폰용 HTTPS 주소 연결

DSM **제어판 → 로그인 포털 → 고급 → 역방향 프록시**에서 이 앱 전용 호스트를 설정합니다. NAS 관리자 화면과 다른 호스트를 사용하세요.

| 항목 | 값 |
| --- | --- |
| 원본 프로토콜 | HTTPS |
| 원본 호스트 | 본인이 소유·설정한 타이머 전용 도메인 |
| 원본 포트 | 443 |
| 대상 프로토콜 | HTTP |
| 대상 호스트 | 127.0.0.1 |
| 대상 포트 | 3130 |

원본 도메인과 일치하는 **아이폰이 신뢰하는 인증서**를 DSM에서 연결해야 합니다. 도메인이 실제 NAS로 해석되는 DNS 설정도 필요합니다. `.synology.me` 같은 DDNS 주소를 만든 것만으로 인증서·내부 DNS 설정까지 완료되지는 않습니다. QuickConnect 주소만 입력하는 방식은 이 API의 연결 방법으로 지원하지 않습니다.

집 안에서만 사용한다면 집 와이파이에서 해당 HTTPS 호스트가 NAS로 연결되도록 구성하세요. 타이머 서버는 NAS에서 SmartThings로 나가는 HTTPS 연결만 있으면 M5 명령을 전송할 수 있습니다. **외부 제어를 위해 공유기 포트를 먼저 열 필요는 없습니다.** 집 밖에서도 앱으로 조작할 계획이라면 VPN 또는 별도로 검토한 HTTPS 접근 구성이 필요합니다. DSM 관리자 포트를 인터넷에 공개해서 해결하지 마세요.

아이폰 Safari에서 `https://본인의-타이머-도메인/health`를 열어 `{"ok":true}`가 나오면 HTTPS 경로가 연결된 것입니다. 이 응답은 인증 정보나 모니터 상태를 공개하지 않습니다.

## 4. 앱 연결과 실제 테스트

1. 앱 → 부모님 → M5 자동 끄기 연결.
2. 위 HTTPS 주소와 `APP_API_KEY` 입력.
3. ‘연결 확인하고 저장’으로 SmartThings 기기 상태를 조회합니다. 이 동작은 모니터를 끄지 않습니다.
4. 이후 부모가 시험할 수 있는 때에 서버 한도를 1분으로 설정하고 ‘보기 시작’을 눌러 M5 끄기 동작을 확인합니다. 앱 기본 시간 조절은 5분 단위이므로 앱만으로 시험할 때는 **5분**을 사용하세요. 실제 시험 전 아이에게 알리고 진행하세요.
5. 앱 종료 후에도 시간이 차감되고 끄기가 실행되는지 확인합니다.

SmartThings의 명령 수락과 실제 전원 꺼짐은 다릅니다. 모니터가 오프라인이거나 토큰이 만료되면 끄기에 실패할 수 있으니 앱의 실패 표시와 M5 상태를 함께 확인하세요.

## 유지 관리

- `unless-stopped` 정책으로 NAS·Docker 재시작 시 서버를 다시 실행합니다. NAS가 꺼져 있는 동안에는 모니터를 끌 수 없습니다.
- 타이머 기록은 `timer-data` 이름의 Docker 볼륨에 저장합니다. 컨테이너 재생성은 가능하지만 **프로젝트 삭제 시 볼륨까지 지우면 기록이 사라집니다.**
- NAS 시각 동기화(NTP)를 활성화하세요. 앱·서버의 현재 날짜 기준은 한국 시간으로 맞춰 사용하세요.
- 토큰을 교체한 후에는 컨테이너를 **재생성**해 새 환경 변수를 적용합니다. 단순 프로세스 재시작만으로 변경된 `.env`가 적용되지는 않습니다.
- 코드 업데이트 시 프로젝트를 다시 빌드하되 데이터 볼륨을 보존합니다.
